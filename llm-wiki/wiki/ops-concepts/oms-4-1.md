> [!summary] Key takeaways
- Target cycle time caps total task time per workstation.  
- Assign tasks respecting precedence; use priority rules (Longest Task Time, most followers).  
- Goal: minimize number of stations → maximize efficiency.  
- Small tweaks (e.g., 128 s → 127 s) can erase idle time and raise output.  
- Heuristics guide allocation but optimality isn’t guaranteed; compare with the theoretical minimum.

## 1. Core concepts
> [!info] **Line balancing** – distributing work so each station’s total task time ≤ target cycle time while honoring precedence.
> [!info] **Target cycle time** – maximum time a workstation may spend per unit, derived from demand and available production time.  
> [!warning] Frequent re‑assignment of tasks harms worker performance and complicates capacity planning.

## 2. Standard workflow
1. **Compute target cycle time**  
   - Cycle = (available shift minutes × 60) ÷ required units.  
2. **List tasks** with processing time and precedence graph.  
3. **Calculate minimum stations**  
   - \(N_{min}= \lceil \frac{\sum\text{task times}}{\text{cycle time}} \rceil\).  
4. **Allocate tasks** using priority heuristics (see §3).  

## 3. Priority rules for task selection
| Rule | Rationale | Tie‑breaker |
|------|-----------|-------------|
| **Longest Task Time (LTT)** | Packs large chunks early, leaving smaller gaps later. | Number of followers |
| **Most Followers** | Unlocks the greatest number of subsequent tasks. | LTT |

> [!example] **Bicycle assembly** (9 tasks, cycle = 128 s)  
> - Total raw time ≈ 427 s → need ≥ 4 stations.  
> - Station 1: Task 1 (60 s) → 62 s left → pick Task 2 (LTT) → station full.  
> - Continue with eligible tasks respecting precedence.

## 4. Allocation procedure (table‑driven)
1. Start a new station with full cycle time.  
2. Identify **eligible** tasks (all predecessors already assigned).  
3. Apply priority rules → assign task, subtract its time.  
4. Update eligibility list; repeat until no task fits.  
5. Move to next station and repeat.

> [!warning] Adding a task that exceeds the remaining time creates idle time; avoid by respecting the cycle‑time limit.

## 5. Efficiency & performance metrics
> [!info] **Utilization / Efficiency**  
\[
\text{Efficiency}= \frac{\sum\text{task times}}{\text{#stations}\times\text{cycle time}}
\]

- Higher efficiency ⇔ fewer stations.  
- Example: 20 s idle on a 128 s cycle → efficiency ≈ 74.5 %.

**Maximum output rate** (no station limit) = 1 / (bottleneck task time).  
If longest task = 92 s → max ≈ 0.0109 units / s (≈ 39 units / hour).

## 6. Practical tips
- **Buffer vs. scheduling**: Prefer better task sizing/ordering over inventory buffers.  
- **Heuristic validation**: If a heuristic reaches the theoretical minimum (Σtime ÷ cycle time rounded up), the solution is provably optimal.  
- **Small adjustments**: Reducing cycle time by 1 s can eliminate idle seconds and increase output (e.g., 225 → 226 units).  
- **AI assistance**: Modern tools can generate precedence tables and test millions of allocations instantly.  
- **Manual environments**: When software is unavailable, follow the step‑by‑step allocation table; keep notes of eligibility changes.

## 7. Common pitfalls
| Pitfall | Why it hurts |
|---------|--------------|
| Ignoring precedence | Produces infeasible schedules. |
| Relying on inventory buffers | Masks underlying bottlenecks. |
| Using LTPR blindly | Not optimal for many problems; not required on exam. |
| Over‑splitting tasks without cost benefit | Increases setup/handling time. |

## Key terms
| Term | Meaning |
|------|---------|
| Target cycle time | Upper limit of work per station, set by demand & shift length. |
| Precedence relationship | Order constraint; a task can only follow its predecessors. |
| Eligible task | A task whose all predecessors are already assigned. |
| Longest Task Time (LTT) | Heuristic that selects the longest remaining task. |
| Efficiency | Ratio of total processing time to (stations × cycle time). |
| Theoretical minimum stations | \(\lceil \frac{\sum\text{times}}{\text{cycle}} \rceil\); may be unattainable due to discreteness. |
